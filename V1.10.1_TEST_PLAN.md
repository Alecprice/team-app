# Team APP V1.10.1 — Live Staging Test Plan

Run this plan against a Cloudflare preview/staging deployment wired to the Neon release-candidate branch. Do not apply the V1.10.1 migration to Neon `main` or invite real families until these gates pass.

## 1. Build identity and deployment

- [ ] Deploy the exact branch/commit under test.
- [ ] Open `/build-info.json` and confirm app `team-app`, version `1.10.0`, expected environment, and exact Git commit SHA.
- [ ] Run the Production Smoke workflow with the expected commit SHA.
- [ ] Confirm root, manifest, service worker, cloud bundle, hardening runtime, icons, CSP, HSTS, anti-framing, referrer and permissions headers.
- [ ] Confirm invite URLs are not persisted as service-worker Cache Storage keys.

## 2. Auth and shared-device privacy

- [ ] Configure staging Neon Auth so email verification is actually sent/required.
- [ ] Create Adult A account and verify email.
- [ ] Confirm an unverified account cannot create a cloud team, accept an invitation, or redeem a join code.
- [ ] Verify forgot-password email/recovery flow end to end.
- [ ] Sign out and confirm the underlying coach workspace is not exposed.
- [ ] Sign in as Adult B on the same browser/device and confirm Adult A local team state, local files, and E2EE keys do not appear.
- [ ] Switch back to Adult A and confirm Adult A state returns.
- [ ] Confirm first-login migration preserves any pre-login/unpublished local workspace.
- [ ] Open `?demo=1` and confirm demo data cannot read or modify real-account state.

## 3. Team creation, guardian access, and revocation

- [ ] Create a synthetic coach team.
- [ ] Add at least two synthetic athletes.
- [ ] Create a guardian invitation and confirm an athlete link is required.
- [ ] Create/redeem a guardian join code and confirm an athlete link is required.
- [ ] Confirm the guardian sees only authorized/member-projected state: no coach notes, player development, lineups, game sessions, generic attendance, or private document metadata.
- [ ] Confirm guardian event Availability only returns the linked athlete(s).
- [ ] Confirm guardian cannot upload/use Medical / Safety document category.
- [ ] Change a member role and verify the new role takes effect after refresh/session update.
- [ ] Revoke a pending invitation and verify it can no longer be accepted.
- [ ] Remove a guardian/member and verify team access and conversation membership are denied immediately online.
- [ ] Verify linked guardian relationships are removed with team access removal.
- [ ] Transfer team ownership to another adult and verify the old owner becomes admin.
- [ ] Confirm owner cannot be removed without ownership transfer.

## 4. Offline and synchronization

- [ ] Install the PWA.
- [ ] Open online, then switch offline.
- [ ] Make roster/lineup/Game Day changes and confirm persistent Offline / saved status.
- [ ] Close/reopen while offline and confirm the authenticated account's cached workspace is still available as designed.
- [ ] Reconnect and confirm queued changes replay once.
- [ ] Trigger rapid edits plus manual Sync and confirm serialized sync does not create a false same-device revision conflict.
- [ ] Open two tabs and confirm account-change warnings/cross-tab behavior are understandable.
- [ ] Create a real two-device concurrent edit and confirm conflict UI appears instead of silent overwrite.
- [ ] Test Use cloud copy and Keep this device copy explicitly.
- [ ] Simulate local-storage quota/write failure and confirm a persistent warning says changes are temporary.

## 5. Messaging and E2EE

- [ ] Create coach/team/direct conversations.
- [ ] Confirm guardians are not offered unrelated guardians as direct-message targets by default.
- [ ] Send messages between two synthetic adults and verify plaintext is not stored by the server path.
- [ ] Force a network failure during send and confirm the typed draft remains in the input.
- [ ] Put the app in the background and confirm message polling is reduced/suspended until visible.
- [ ] Remove a conversation member and confirm they lose future conversation access.
- [ ] Rotate to a new E2EE key version and verify existing envelope rows cannot be overwritten.
- [ ] Verify old retained-device history and new-key future messages behave as documented.

## 6. Documents and forms

- [ ] Upload a normal team document and verify role visibility.
- [ ] Confirm cloud document metadata comes from the authorized document service rather than member team-state snapshots.
- [ ] Confirm Medical / Safety category is unavailable/rejected.
- [ ] Acknowledge a document from guardian account and verify status.
- [ ] Create/assign/submit a form with linked athlete.
- [ ] Verify required fields/signature behavior and duplicate submission constraints.
- [ ] Confirm coach-only/private forms cannot be assigned to unauthorized guardian accounts.

## 7. Mobile usability and accessibility

- [ ] Test 320px-wide phone, modern iPhone portrait, landscape, and desktop.
- [ ] Verify touch targets around primary/mobile actions are comfortable and no adjacent Game Day buttons cause accidental taps.
- [ ] Verify roster/event/document search appears on large lists and filters correctly.
- [ ] Verify every form control has a programmatic accessible label.
- [ ] Verify modal focus stays inside the active dialog and returns to the trigger when closed.
- [ ] Verify reduced-motion preference suppresses animation/transition movement.
- [ ] Verify persistent storage/auth errors remain visible instead of disappearing as short toasts.
- [ ] Test keyboard-only navigation for tabs/forms/buttons and core lineup alternatives.

## 8. Scale/performance

- [ ] Confirm CI extreme-season budget remains under 2.5 seconds for each audited navigation on the CI runner.
- [ ] Confirm serialized synthetic extreme state remains below 1.5 MiB.
- [ ] Seed a realistic multi-team account and measure login-to-active-team-ready time.
- [ ] Measure message history load/poll behavior under a long conversation.
- [ ] Verify database query plans use the new membership/message indexes once realistic staging rows exist.

## 9. PWA upgrade/recovery

- [ ] Install the prior V1.10 build, then deploy V1.10.1 candidate and test upgrade.
- [ ] Confirm existing tab is not destructively replaced mid-edit by a new service worker.
- [ ] Confirm offline reload works after upgrade.
- [ ] Confirm browser Back/Forward/hash shortcuts still navigate correctly.
- [ ] Confirm notification click opens/focuses the intended Schedule destination.

## 10. Production promotion gate

Only after all mandatory items above pass:

- [ ] Configure the single canonical production Cloudflare origin everywhere.
- [ ] Require email verification in production Neon Auth and remove inappropriate localhost/unused auth surfaces.
- [ ] Apply `sql/upgrade-v1.10-to-v1.10.1-hardening.sql` to Neon `main` using the reviewed migration workflow.
- [ ] Protect GitHub `main` and require Team APP CI/release gate.
- [ ] Protect Neon production branch and document rollback/restore steps.
- [ ] Run Production Smoke against the exact promoted Git SHA.
- [ ] Delete all synthetic staging/production QA data.

## Still not broad-launch complete after V1.10.1 code hardening

The following remain architectural/operational projects rather than one-night patches: move primary app state from localStorage to IndexedDB, normalize/delta-sync high-churn team data instead of whole snapshots, replace whole-app rerenders in high-frequency views, deploy private object storage for production documents, increase/test recovery retention, finish full notification-center/push delivery, and complete sport-by-sport rule/content validation.
